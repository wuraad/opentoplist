# 模块E：质量保障与发布回滚预案

## 1) API 自动化测试范围

- Auth：正确登录、错误密码、被封用户
- Device：设备绑定、重复绑定、超限绑定
- Node Route：区域路由、无健康节点、被封用户
- Risk：低风险放行、高风险封禁
- Complaint Trace：有命中/无命中

## 2) 端到端回归（E2E）

1. 新用户登录 -> 拉取节点 -> 建连成功
2. 弱网注入 -> 客户端重试 -> 自动切换节点
3. 风控命中高风险 -> 限速/隔离/封禁动作执行
4. 上游投诉模拟 -> 反查会话 -> 用户策略更新

## 3) 压测计划

- 并发会话：500 / 1000 / 3000
- 弱网模型：高延迟（300ms）、丢包（10%）、抖动（80ms）
- 断线重连：每 30 秒随机断开 10% 会话

关注指标：
- 建连成功率
- 平均重连时长
- 99 线延迟
- 风控触发率与误杀率

## 4) 发布策略

- 蓝绿发布（推荐）：
  1. 新版本在 green 环境跑冒烟
  2. 灰度 5% -> 20% -> 50% -> 100%
  3. 每阶段观察 30 分钟核心指标

## 5) 回滚预案

触发条件（任一满足立即回滚）：
- 建连成功率下降 > 5%
- 关键区域节点异常率 > 3%
- 风控误杀上升 > 基线 2 倍

回滚步骤：
1. 客户端停止升级并回切旧配置
2. 控制平面回滚上一策略版本
3. 网关恢复上个稳定 nftables / tc 模板
4. 通知值班与客服并记录事故复盘
